# 阶段 4 方案：PDF 导出 + 图片导出

> 确认日期：2026-10-17。三个决定点按推荐：「保存本页」改为「导出」入口；跨页模式下封面、封底按单页导出；两版 PDF 页面尺寸均为 21×28 cm。

## 目标
1. 导出 PDF 相册：分享版 / 打印版，发送到微信聊天、打开预览，显示进度
2. 保存为图片：选择全部页或指定页；可按跨页导出
3. 导出前检查空照片框（阶段 3 记下的需求）

## 1. 导出页 `pages/export`
编辑页工具栏的「保存本页」换成「导出」，进入导出页（保存单页的功能并入「保存为图片」，并默认选中当前页）。

```
┌ 导出 PDF 相册 ─────────────────────┐
│ ◉ 分享版  每页 1080×1440，约 0.3MB/页 │
│ ○ 打印版  每页 2480×3307，约 1.5MB/页 │
│ [ 生成 PDF ]                         │
│ 生成后：[发送到聊天] [打开预览]       │
└──────────────────────────────────────┘
┌ 保存为图片 ────────────────────────┐
│ [单页 1080×1440] [跨页 2160×1440]   │
│ 封面 环衬 扉页 P1 P2 … 封底  [全选]  │
│ [ 保存到相册（3 张） ]              │
└──────────────────────────────────────┘
生成中：进度条「正在生成 第 3 / 24 页」+ [取消]
```

## 2. 空照片框检查
- 生成 PDF 或保存图片前，统计将导出的页中的空照片框。
- 有空框时弹窗：「还有 N 个空照片框」，按钮「返回填充」/「直接导出」。
- 返回填充：回到编辑页，并跳到第一个有空框的页（沿用跨页管理用的 eventChannel 跳转）。
- 直接导出：空框按占位色导出。

## 3. PDF 生成
- 每页流程：`renderPage` → 离屏 canvas → JPG 文件 → 读成 ArrayBuffer → 追加写入 PDF 文件 → 立即删除 JPG、释放图片。
- 自写轻量 PDF 生成器 `core/export/pdf.js`：每页一张 JPG（`/DCTDecode`），**边生成边追加写文件**（`FileSystemManager.appendFile`），不在内存中拼整本书，避免打印版内存不足。最后写页树、目录、xref、trailer。
- 页面物理尺寸两版相同：21×28 cm（595.28 × 793.70 pt），分辨率不同。
- PDF 元数据：Title 用书名（UTF-16 编码，支持中文），Producer 为 MyZine。
- 分享版用压缩图（`display`）；打印版每页从原图读取（`original`），原图加载失败时退回压缩图。
- 每页只加载这一页用到的照片（不是整个跨页），打印版内存更可控。
- 跨页大图（`side: full`，阶段 5 才有）在 PDF 中拆成左右两页。
- 文件名：书名；书名为空时「MyZine相册_20261017」；去掉文件名非法字符；写入 `wx.env.USER_DATA_PATH`，同名覆盖。
- JPG 质量：分享版 0.85，打印版 0.93。
- 完成后显示「已生成：N 页，X MB」。
- 生成中：屏幕常亮（`wx.setKeepScreenOn`），每页之间检查「取消」；离开导出页时提示「正在导出，确定离开吗」。
- 失败处理：画布创建失败（机型不支持大尺寸）提示改用分享版；写文件失败（存储空间不足）给出提示。

## 4. 交付与清理
- 发送到聊天：`wx.shareFileMessage({ filePath, fileName })`（需用户点击触发）。
- 打开预览：`wx.openDocument({ filePath, fileType: 'pdf', showMenu: true })`。
- 两种方式都需真机测试；开发者工具不支持 `shareFileMessage`。
- 文件大小上限：官方文档（基础库 2.16.1 起支持，仅能由点击触发）**未写明大小上限**，社区也没有可靠数据。因此不写死阈值，按实际结果处理：发送失败（非用户取消）时弹窗说明「文件可能过大（当前 X MB）」，建议改用分享版，或「打开预览」后用右上角菜单转发。真机测试打印版时记录实际能否发送，补充到本文档。
- 本地存储上限：本地用户文件与缓存文件合计最多 200MB（官方文档），写入失败时提示存储空间不足。
- 清理：每页的临时 JPG 用完即删；PDF 保留到离开导出页或开始下一次导出时删除。

## 5. 保存为图片
- 单页模式：选中的页逐张渲染为 1080×1440 并保存到相册。
- 跨页模式：选择单位变为跨页，渲染 2160×1440 横图（`renderSpread`，不画中缝阴影）；**封面、封底按单页 1080×1440 保存**，不留半边空白。
- 逐张保存，显示进度；相册权限沿用现有处理（拒绝时引导去设置），权限失败时停止后续保存。

## 验证
- 离线：用 Node 模拟文件系统生成 PDF，检查结构和 xref 偏移正确。
- 真机：分享版、打印版各导出一次，发送到文件传输助手，在手机和电脑上打开，页序、清晰度、无变形；打印版照片清晰度明显高于分享版。
- 进度和取消；取消后无残留文件。
- 空框提示；返回填充跳到正确页。
- 图片：单页、跨页模式各保存几张；封面、封底在跨页模式下是单页图。
- 拒绝相册权限后的引导。
- 书名为空、含特殊字符时的文件名。
- iPhone 和安卓分别测试：「打开预览」后能否用右上角菜单转发、保存到手机。
- 打印版能否通过「发送到聊天」发出，记录文件大小和结果。

## 真机测试记录（2026-10-17）
- 打印版：19 张照片生成的 PDF 约 18.6 MB，可以通过「发送到聊天」发出。更大的文件能否发送仍未知，失败时有替代方案提示。
- 「打开预览」后转发、保存：iPhone 正常；**安卓未测试**（暂无设备），有安卓机时补测。
